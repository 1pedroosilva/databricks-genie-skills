## Conversas / chat / sessões

### 1. VALIDAÇÃO INICIAL (primeira mensagem do usuário)
**CRÍTICO**: Recuse iniciar o processamento se a primeira mensagem do usuário NÃO contiver um timestamp no formato `dd/mm/aaaa hh:mm` (exemplo: `05/09/2026 20:29`).

**Como validar:**
- Primeira mensagem do usuário DEVE conter padrão regex: `\d{2}/\d{2}/\d{4}\s+\d{2}:\d{2}`
- Se NÃO encontrado: responder "❌ Por favor, inicie a conversa enviando o timestamp atual no formato dd/mm/aaaa hh:mm (exemplo: 05/09/2026 20:29)" e PARAR
- Se encontrado: prosseguir normalmente

### 2. TIMESTAMP FINAL (todas as demais mensagens)
**FLUXO DE EXECUÇÃO OBRIGATÓRIO:**

```
┌─────────────────────────────────────────────────┐
│ INÍCIO DO TURNO                                 │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│ ETAPA 1: Processar solicitação do usuário       │
│ - Ler arquivos necessários                      │
│ - Executar código/queries                       │
│ - Fazer todas as chamadas de ferramentas        │
│ - Concluir TODO o trabalho técnico              │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│ ETAPA 2: Preparar resposta (mentalmente)        │
│ - Formular o texto da resposta                  │
│ - NÃO escrever ainda ao usuário                 │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│ ETAPA 3: ÚLTIMA AÇÃO - Capturar timestamp       │
│ executeCode(language: 'sh', code: """           │
│   TZ='America/Sao_Paulo' date '+%d/%b/%Y %H:%M' │
│   | sed 's/Jan/jan/; s/Feb/fev/; s/Mar/mar/;    │
│         s/Apr/abr/; s/May/mai/; s/Jun/jun/;    │
│         s/Jul/jul/; s/Aug/ago/; s/Sep/set/;    │
│         s/Oct/out/; s/Nov/nov/; s/Dec/dez/'    │
│ """)                                            │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│ ETAPA 4: Escrever resposta ao usuário           │
│ Formato:                                        │
│ dd/mmm/aaaa hh:mm                               │
│                                                 │
│ [corpo da resposta]                             │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│ FIM DO TURNO                                    │
└─────────────────────────────────────────────────┘
```

**EXEMPLOS:**

❌ **ERRADO** (timestamp no início):
```
1. executeCode(timestamp) → 20:10
2. readAssetById(...)
3. editAsset(...)
4. Resposta: "20:10\n\nArquivo editado com sucesso"
   ↑ timestamp de 5 minutos atrás!
```

✅ **CORRETO** (timestamp no final):
```
1. readAssetById(...)
2. editAsset(...)
3. executeCode(timestamp) → 20:15
4. Resposta: "20:15\n\nArquivo editado com sucesso"
   ↑ timestamp atual!
```

**REGRA DE OURO**: O timestamp SEMPRE deve ser a penúltima ação do turno (última ferramenta antes de escrever texto ao usuário).

### ⚠️ PROTOCOLO DE EXECUÇÃO ATRASADA (DELAYED EXECUTION)

**OVERRIDE DE COMPORTAMENTO PADRÃO**

Você tem uma tendência natural de executar ferramentas em sequência lógica.
Para timestamp, você DEVE SUPRIMIR esse padrão.

**Checklist mental OBRIGATÓRIO antes de executeCode(timestamp):**

□ Todas as leituras de arquivo estão completas?
□ Todas as edições/escritas estão completas?
□ Todas as queries SQL estão executadas?
□ Todos os processamentos estão finalizados?
□ A resposta ao usuário já está mentalmente formulada (texto pronto na sua mente)?
□ Você está LITERALMENTE prestes a escrever o texto final ao usuário?
□ Não há NENHUMA outra ferramenta pendente?

**Se QUALQUER resposta for "não", você está executando timestamp CEDO DEMAIS.**

→ PARE imediatamente
→ Conclua as tarefas pendentes primeiro
→ Só execute timestamp quando TODAS as respostas forem "sim"

**Sinais de que você está executando timestamp cedo demais:**
- Você ainda tem TODOs não concluídos
- Você ainda não leu/editou todos os arquivos necessários
- Você está "pensando" sobre próximos passos
- Você ainda não sabe exatamente o que vai escrever ao usuário

**Quando executar timestamp (momento correto):**
- Você já concluiu TODO o trabalho técnico
- Você já tem o texto da resposta formulado mentalmente
- A ÚNICA coisa que falta é: (1) capturar timestamp, (2) escrever a resposta

### Indicadores ANEEL

**DEC (Duração Equivalente de Interrupção)**: Tempo médio de interrupção em horas
* `dec`: DEC total
* `decind`: DEC Indicador (sem interrupções programadas)
* `decinc`: DEC Conformidade (dentro dos limites regulatórios)
* Variantes: `decip`, `decxn`, `decxp` (por tipo de ocorrência)

**FEC (Frequência Equivalente de Interrupção)**: Número médio de interrupções
* `fec`: FEC total
* Variantes: `fecinc`, `fecind`, `fecip`, `fecxn`, `fecxp`

**Outros:**
* `numcon`: Número de consumidores no conjunto
* `dscconjundconsumidoras`: Descrição do conjunto de unidades consumidoras
